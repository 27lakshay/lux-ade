# Domain documentation

Use a single shared domain context in `CONTEXT.md`. The monorepo implementation is
planned; separate package glossaries would duplicate shared identities today.

Before changing ownership, lifecycle or contracts, read `CONTEXT.md`, the relevant
v1 domain spec and the shared reliability spec. The architecture proposal supplies
rationale; the current architecture map locates prototype code. Consult the spec's
delivery decision register before treating package or coverage choices as settled.

No separate ADR collection is configured. Record agreed decisions in the relevant
spec and delivery decision register, keeping scope IDs stable.
