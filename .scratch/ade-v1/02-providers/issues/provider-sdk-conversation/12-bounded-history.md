# 12 — Load bounded history with correct tool attribution

Status: complete
Type: implementation ticket

**Parent:** [TypeScript provider SDK and conversation UI](../../provider-sdk-conversation-ui.md)

**What to build:** Read long histories in bounded pages without mixing source generations or attaching tool output to an unrelated call.

**Blocked by:** [01 — Open a readable production conversation](01-production-conversation.md), [02 — Install and inspect an Effect provider worker](02-effect-worker-installation.md)

**Spec coverage:** PC17, PC29, PC34, PC35. This ticket contributes the behavior described below; shared rows require the other contributors in the [acceptance coverage](README.md#acceptance-coverage).

## Acceptance criteria

- [x] Expose snapshot-bound history reads through the public worker contract and existing client projection. Native cursors differ from ADE feed positions; weaker consistency is disclosed.
- [x] Bind cached history to execution/account context, lineage and resolved source identity. Same-timestamp size changes and invalidation epochs prevent old reads replacing new state.
- [x] Deduplicate matching in-flight reads only. Temporary refusals retain identified stale content with an error and bounded query backoff, not a permanent missing-history cache.
- [x] Ordinary conversation.get snapshots and live Store.messages retain at most 32 messages and 512 KiB encoded per page. Older history uses native-history paging; its 32-item pages and 512-item/8 MiB aggregate projection bounds are separate from ADE revisions/sequences and never delete durable messages.
- [x] Bound pages, retained bytes and decoded memory, including a single oversized transcript. Page/stream or return explicit limits; never exempt the newest item or claim truncated history complete.
- [x] Retain orphaned/paged tool results with readable incomplete context or fetch their identified call. Compaction and reused names do not fabricate new executions or text-based joins.
- [x] Preserve documented timestamp units, source and unknown native values. Desktop and CLI/SDK agree on page identities, stale snapshots and retained core content.
- [x] Record commands, native reports, observable outcomes and explicit failed, skipped or prerequisite-blocked coverage. Pass the required static gate and this slice’s real-process/built-desktop acceptance before claiming completion.

## Testing decisions

Use real-process history peers with large content, shared native IDs, changed source generations and late reads; test paged tool context and desktop loading/error states.

Read the [shared delivery rules](README.md#delivery-rules) before implementation. Extend reusable fixtures and conformance support as this slice lands; later evidence tickets do not replace its acceptance.
