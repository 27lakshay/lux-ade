# 01 — Open a readable production conversation

Status: complete
Type: implementation ticket

**Parent:** [TypeScript provider SDK and conversation UI](../../provider-sdk-conversation-ui.md)

**What to build:** Open an existing conversation in the approved production pane and read its retained history and execution context without starting or stopping agent work.

**Blocked by:** None — can start immediately

**Spec coverage:** PC23, PC28, PC29, PC36. This ticket contributes the behavior described below; shared rows require the other contributors in the [acceptance coverage](README.md#acceptance-coverage).

## Acceptance criteria

- [x] The approved conversation design displays the workspace, host, provider and account context from authoritative state, with readable retained text and core tool summaries.
- [x] Opening the pane uses the existing client projection, typed preload and stream bridge. Empty, loading, unavailable and failed reads have explicit states; the renderer acquires no native provider or credential access.
- [x] Two tabs can display the same conversation with independent local view state and one authoritative history. Closing either view releases its subscriptions and preserves runtime-owned work.
- [x] CLI/SDK inspection and the built desktop agree on conversation identity and retained records. Missing specialized renderers do not hide core-readable content.
- [x] A pending read or subscription callback completing after view disposal cannot repopulate a departed view or a successor conversation.
- [x] Record commands, native reports, observable outcomes and explicit failed, skipped or prerequisite-blocked coverage. Pass the required static gate and this slice’s real-process/built-desktop acceptance before claiming completion.

## Testing decisions

Read real daemon-owned fixtures in the built desktop; exercise multiple tabs, unavailable providers and teardown during pending reads. Keep selection and local projection tests in browser mode.

Read the [shared delivery rules](README.md#delivery-rules) before implementation. Extend reusable fixtures and conformance support as this slice lands; later evidence tickets do not replace its acceptance.
