# 09 — Manage custom themes and ADE import/export

Status: in-progress
Type: implementation ticket

**Parent:** [App, terminal and code theming](../../theming.md)

**What to build:** Import, inspect, duplicate, rename, replace, delete and export custom themes without losing edits or confusing display names with identity.

**Blocked by:** [08 — Preview appearance safely before applying it](08-safe-preview.md)

**Spec coverage:** TH07, TH09, TH28, TH30. User stories 23–25, 48–52, 57, 62, 64, 73, 76. Coverage is this ticket’s contribution; shared acceptance rows require the other contributors listed in the [ticket index](README.md#acceptance-coverage).

## Acceptance criteria

- [x] Versioned JSON/JSONC definitions validate supported app/terminal/syntax sections, required roles, literal sRGB/allowed alpha or symbolic values, mode and provenance before mutation. Unsupported versions follow D19 and fail visibly.
- [x] Import preview reports source locations, normalization, unsupported extensions and required errors. Batch import atomically installs only the explicitly accepted valid set.
- [x] Stable namespaced IDs survive rename. Conflicts offer revision-checked replacement or a distinct ID; duplicate display names never authorize replacement.
- [x] Bundled definitions remain immutable; duplicate/save-as creates a custom definition. Deletion shows affected selections and deterministic same-mode fallbacks; restore-defaults is available in safe mode.
- [x] Export emits a definition or self-contained resolved pack with equivalent supported round-trip values. Explicit file writes have visible overwrite behavior and atomic replacement.
- [x] Desktop, CLI and SDK provide equivalent list/inspect/validate/install/update/remove/select/reset/export outcomes and machine-readable errors. Color import leaves unrelated appearance settings unchanged.
- [x] Installed definitions remain usable after source files disappear. Origin, source version/digest and available author/license metadata survive library operations.
- [x] Record observable acceptance evidence and run the required repository checks; identify any remaining prerequisite or failed check explicitly.

## Testing decisions

Prove valid and malformed imports, atomicity, revision conflicts and export equivalence over public operations; drive file import and replacement choices in built Electron using scratch files.

Read the [shared delivery rules](README.md#delivery-rules) before implementation.

2026-09-30 — Definition file export slice (coordinated packs remain open):

- Desktop, CLI and SDK can now write the daemon's serialized definition to an explicit host destination. Serialization still uses the existing revision-checked `themes.export` query; no new daemon file-writing authority or effect operation was introduced. This does not change selections, definition data or unrelated appearance preferences. A current-format resolved pack is still absent, so the export criterion and ticket remain open.
- The SDK exposes `writeThemeExport` and typed `ThemeFileExport`/`ThemeFileExportError` values. It writes UTF-8 plus one trailing newline to an exclusively created private temporary file beside the destination, synchronizes and closes it, then publishes the complete bytes. New files use an exclusive hard link, which rejects a target that appeared concurrently. Explicit replacements use a same-filesystem rename. Handled failures close the handle and remove the writer's temporary file; an existing target never receives partial bytes. This establishes atomic visibility for the macOS/local filesystem scope, not a power-loss or network-filesystem durability guarantee.
- `ade themes export ID [REVISION] --output PATH` refuses existing paths. `--overwrite` requires an output path and explicitly authorizes replacement. Without an output argument the existing JSON-data response is preserved. The success receipt includes the absolute destination, theme ID/revision, byte count and SHA-256. CLI errors use machine-readable conflict/unavailable categories; SDK callers receive the corresponding typed error with its cause.
- Electron main serializes before opening the native save picker. The renderer sends only an ID and captured revision, never a destination path or source bytes. Cancel returns without a write. An existing regular file or symlink requires an explicit Replace file confirmation with Cancel as the default. Replacing a symlink replaces that directory entry and never writes through to its target. Non-file destinations are rejected. The suggested filename is sanitized and bounded; async filesystem operations avoid blocking main. A stock library button shows success, cancellation and retryable failures.
